# Contributing to in/acc

Thank you for your interest in Indic Accelerationism. This is an open movement and every contribution matters -- whether you're a researcher, developer, policy analyst, designer, writer, or organizer.

---

## Ways to Contribute

### By Pillar

in/acc is organized around seven pillars. Find the one that matches your skills:

| Pillar | You might... |
|--------|-------------|
| **Research Mediation** (Anvikshiki) | Write literature reviews, synthesize data, produce evidence briefs |
| **Design Proposals** (Kalpana) | Draft technical specs, system architectures, UX designs |
| **Policy Advocacy** (Nitivada) | Analyze policy, draft recommendations, engage with institutions |
| **Change Management** (Yojana) | Plan rollouts, manage stakeholder communication, facilitate adoption |
| **Build & Execution** (Nirmana) | Write code, build prototypes, ship tools and platforms |
| **Deployment & Operations** (Vyavahara) | Set up infrastructure, maintain systems, monitor performance |
| **Marketing & Consultation** (Samvada) | Create content, grow the community, advise on strategy |

### By Activity

- **Improve the Manifesto** -- Refine language, add evidence, propose new sections
- **Propose a Project** -- Open an issue describing a new initiative aligned with in/acc goals
- **Contribute Research** -- Add to the knowledge base with studies, data, or analysis
- **Build Something** -- Prototype a tool or platform that advances an in/acc priority area
- **Spread the Word** -- Write about in/acc, share with your network, bring in new contributors

## How to Contribute on GitHub

### Reporting Issues & Proposing Ideas

1. Check [existing issues](../../issues) to avoid duplicates
2. Open a new issue with a clear title and description
3. Tag it with the relevant pillar or project area
4. Include context: what problem does this solve? Who benefits?

### Submitting Changes

1. **Fork** this repository
2. **Create a branch** from `main` with a descriptive name (e.g., `research/judiciary-ai-survey`)
3. **Make your changes** -- keep commits focused and well-described
4. **Submit a pull request** against `main`
5. **Describe your changes** -- what you did, why, and how it connects to the manifesto or roadmap

### Branch Naming Convention

Use the format `pillar/short-description`:

```
research/corruption-survey
design/smart-toll-architecture
policy/education-access-brief
build/case-prioritization-prototype
ops/community-infra-setup
marketing/launch-blog-post
```

### Writing Style

- Be clear and direct
- Cite sources when making empirical claims
- Use inclusive language
- Keep the Indian context front and center, but draw from global knowledge
- Prefer concrete proposals over abstract commentary

## Community Guidelines

- **Be respectful** -- Disagree on ideas, not on people
- **Be constructive** -- Critique should come with alternatives
- **Be inclusive** -- This movement is for all of India
- **Be honest** -- Acknowledge uncertainty, cite sources, correct mistakes

See the full [Code of Conduct](./CODE_OF_CONDUCT.md) for details.
